# React Native / Expo Code Review

Reviewed against `../SPEC.md` on 2026-11-21 and updated after the targeted corrections described below. Static validation results: ESLint and TypeScript both pass (`eslint . --no-cache`; `tsc --noEmit`). Device-only behavior was not exercised in Expo Go.

1. **[PASS] Acceptance criterion 1 — Navigation is implemented correctly.** The root stack registers `index` and `add`, hides the Home header, and gives the add route the required `"Log Caffeine"` title (`src/app/_layout.tsx:13-22`). Home displays `"Caffeine Meter"` and pushes `/add` from the primary action (`src/app/index.tsx:102-105`, `src/app/index.tsx:205-210`). The native stack back control returns without invoking `save`; persistence only occurs inside `save()` (`src/app/add.tsx:50-79`).

2. **[PASS] Acceptance criterion 2 — The Americano preset auto-fills the required values.** `PRESETS` defines Americano as 95 mg (`src/app/add.tsx:19-24`), and `selectPreset` assigns the preset name and stringified amount to the two controlled inputs (`src/app/add.tsx:44-48`, `src/app/add.tsx:121-150`).

3. **[PASS] Acceptance criterion 3 — Invalid input is visibly rejected before storage is called.** `save()` trims the name and rejects a blank name, a non-integer amount, zero/negative amounts, and out-of-range values, then returns before constructing or saving a log (`src/app/add.tsx:50-63`). The exact required warning is rendered on-screen (`src/app/add.tsx:61`, `src/app/add.tsx:154-158`). Empty mg becomes `Number('') === 0` and is therefore correctly rejected.

4. **[PASS] Acceptance criterion 4 — Saving a custom drink updates history and today's total.** A valid `Cold Brew` / `200` produces a 200 mg log, awaits persistence, and navigates back (`src/app/add.tsx:65-75`). Storage prepends the record and loading also sorts newest-first (`src/lib/storage.ts:17`, `src/lib/storage.ts:27-30`). Home reloads on focus and derives today's intake from the refreshed records (`src/app/index.tsx:41-56`, `src/app/index.tsx:63-68`), so the new record appears at the top and the display becomes `200 / 400 mg` (`src/app/index.tsx:126-130`).

5. **[PASS] Acceptance criterion 5 — The over-limit state uses the specified Crimson Red.** The code treats totals strictly greater than 400 mg as over-limit, applies `#DC2626` to both the numeric intake and progress fill, and retains the uncapped numeric total (`src/app/index.tsx:24-33`, `src/app/index.tsx:67-68`, `src/app/index.tsx:126-139`, `src/app/index.tsx:270-279`). This matches the spec's “more than 400 mg” threshold.

6. **[PASS] Acceptance criterion 6 — The active-caffeine and sleep-safe formulas are correct.** Each log decays with the required five-hour half-life (`src/lib/caffeine.ts:15-20`). Because all records use the same half-life, summing their current active amounts and applying `5 * log2(total / 50)` correctly gives the time until the total reaches 50 mg (`src/lib/caffeine.ts:35-41`). Home rounds the active total to the nearest integer and formats the countdown to one decimal place; 200 mg produces approximately 10.0 hours (`src/app/index.tsx:63-66`, `src/app/index.tsx:112-122`).

7. **[PASS] Acceptance criterion 7 — A normal single-item deletion removes only the selected record and persists it.** Each row passes its own ID to `removeLog` (`src/app/index.tsx:184-190`). Both storage and local state filter only that ID; after the awaited write, the state update immediately recomputes active caffeine and today's intake (`src/app/index.tsx:70-78`, `src/lib/storage.ts:32-35`). Storage failures display an alert instead of falsely removing the UI item (`src/app/index.tsx:71-77`). See finding 11 for overlapping-operation behavior.

8. **[PASS] Acceptance criterion 8 — Clear All is confirmed and correctly resets the UI.** `Clear All` opens an alert with Cancel and destructive confirmation actions; only confirmation removes the storage key and clears local state (`src/app/index.tsx:80-97`, `src/lib/storage.ts:37-39`). An empty list renders the required message (`src/app/index.tsx:193-200`), while totals derive from the now-empty array and become zero (`src/app/index.tsx:63-68`).

9. **[WARN] Acceptance criterion 9 — Persistence is implemented, but the exact force-close/reopen scenario is not verifiable from source alone.** The app uses the exact required key `@caffeine_tracker_logs_v1` (`src/lib/caffeine.ts:1`), serializes the entire array to AsyncStorage (`src/lib/storage.ts:23-30`), and reloads/sorts it whenever Home focuses (`src/app/index.tsx:41-56`, `src/lib/storage.ts:5-20`). This is the correct implementation for restart persistence, but a real iOS/Android Expo Go force-close and reopen is still needed to verify the platform behavior end-to-end.

10. **[PASS] The project passes its required TypeScript check after a targeted route cleanup.** The stale `/explore` triggers were removed from `src/components/app-tabs.web.tsx` and `src/components/app-tabs.tsx`, matching the routes that actually exist under `src/app`. `tsc --noEmit` now completes successfully.

11. **[WARN] Concurrent storage mutations can lose or resurrect records.** `addDrinkLog` and `deleteDrinkLog` each perform a separate read-modify-write sequence with no serialization (`src/lib/storage.ts:27-35`). Two fast deletes can both read the same original array and then overwrite each other; the final stored array may contain an item that the UI already removed. A delete racing Clear All can similarly write records back after the key is removed (`src/lib/storage.ts:32-39`). The ordinary one-action acceptance flow passes, but persistence is not robust under overlapping taps or operations.

12. **[WARN] Malformed persisted JSON is silently treated as an empty history and can then be overwritten.** `loadDrinkLogs` catches parse errors and returns `[]` without surfacing or quarantining the corrupt value (`src/lib/storage.ts:11-20`). A subsequent add/delete operation uses that empty result and replaces the stored history (`src/lib/storage.ts:27-35`). AsyncStorage I/O errors are handled by the screens, but data-corruption errors are hidden from the user and may cause silent data loss.

13. **[PASS] Rounding and threshold comparison now use a consistent value.** Home rounds active caffeine first, then uses that same integer for the sleep-safe calculation and threshold status (`src/app/index.tsx:63-66`, `src/app/index.tsx:115-121`). The displayed number and status can no longer contradict one another near 50 mg.

14. **[WARN] There are no automated tests for the domain or persistence logic.** No test files or test script are present in `package.json:37-44`. The half-life calculation, local-calendar-day boundary, sorting, validation, storage corruption, and mutation races are all behavior where small regressions would be easy to miss. ESLint passes, but linting does not validate these behaviors.

15. **[WARN] Theme values and starter components create avoidable duplication and maintenance drift.** Nearly identical color objects are repeated in `src/app/index.tsx:24-33`, `src/app/add.tsx:26-35`, and `src/app/_layout.tsx:4-7`, despite an existing `src/constants/theme.ts`. The unused starter tab components still contain `"Expo Starter"`, Docs, and the removed Explore route (`src/components/app-tabs.web.tsx:18-76`; `src/components/app-tabs.tsx:6-31`). The stale route already causes finding 10, demonstrating the practical cost of leaving disconnected template code in the checked project.

16. **[WARN] Interactive controls have incomplete accessibility semantics.** The delete button has a useful label, but it and the other `Pressable` controls omit `accessibilityRole="button"` (`src/app/index.tsx:149-151`, `src/app/index.tsx:184-190`, `src/app/index.tsx:205-210`; `src/app/add.tsx:102-113`, `src/app/add.tsx:169-178`). The preset cards also lack explicit combined labels such as `"Americano, 95 milligrams"` and selected-state metadata. The visible UI works, but screen-reader users may receive less clear role and state information than React Native best practice recommends.

## Overall assessment

The core feature code implements acceptance criteria 1-8 correctly, and criterion 9 has the expected AsyncStorage design but needs a real Expo Go restart test for complete verification. ESLint and TypeScript now pass after the targeted fixes. The storage mutation race, silent corrupt-data recovery, missing tests, duplicated theme values, and accessibility gaps remain non-blocking warnings that should be addressed before treating the app as production-ready.
